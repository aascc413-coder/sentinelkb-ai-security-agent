# 国内 OpenAI 兼容模型服务配置指南

SentinelKB 通过 OpenAI 兼容接口调用对话模型和 Embedding 模型。多数国内模型平台或中转站无需安装额外软件，只需要正确填写接口地址、密钥和模型名称。

## 配置文件

真实配置位于 `code/python/.env`，模板位于 `code/python/.env.example`。首次运行 `启动项目.cmd` 时，如果 `.env` 不存在，脚本会自动复制模板。`.env` 已被 Git 忽略。

## 推荐的三种模式

### 完全离线

```env
ENABLE_LLM=0
DISABLE_LOCAL_EMBEDDINGS=1
```

适合首次启动或无 API Key 的情况，具备文档入库、词法检索、IOC/ATT&CK 抽取、Neo4j 写入和规则研判能力。

### 在线问答 + 本地词法检索（优先推荐）

```env
OPENAI_API_KEY=请填写自己的密钥
OPENAI_BASE_URL=https://服务商提供的接口地址/v1
OPENAI_MODEL=服务商控制台显示的准确模型名称
ENABLE_LLM=1
DISABLE_LOCAL_EMBEDDINGS=1
LLM_TIMEOUT_SECONDS=90
LLM_MAX_RETRIES=1
```

大模型负责知识抽取和回答生成，检索侧使用持久化词法索引与 Neo4j，不会调用 Embedding 接口。

### 在线问答 + 在线 Embedding

只有确认服务商账号具备 Embedding 权限后再使用：

```env
OPENAI_API_KEY=请填写自己的密钥
OPENAI_BASE_URL=https://服务商提供的接口地址/v1
OPENAI_MODEL=对话模型名称
EMBEDDING_MODEL=Embedding模型名称
ENABLE_LLM=1
DISABLE_LOCAL_EMBEDDINGS=0
LLM_TIMEOUT_SECONDS=90
LLM_MAX_RETRIES=1
```

对话模型调用成功，不代表同一密钥一定能调用 Embedding。若小型文档入库长时间等待或返回权限错误，先恢复为上一种模式。

## Base URL 和模型名

1. 使用服务商文档中的“OpenAI 兼容地址”，不要填写游乐场或控制台网页地址。
2. 地址通常以 `/v1` 结尾，但不要重复拼接为 `/v1/v1`。
3. 模型名必须与控制台接口模型 ID 完全一致。
4. 修改 `.env` 后必须停止并重新启动 API，刷新网页不会重新加载配置。

## 验证步骤

1. 打开 <http://localhost:8080/api/health>，确认 `status` 为 `ok`、`mode` 为 `online`、`llm.status` 为 `ready`。
2. 在产品页询问一个已入库资料能够回答的问题，结果应包含回答、置信度和参考来源。
3. 上传 `code/samples/rag_test.txt`。只使用词法检索时不会调用 Embedding 接口。

`mode: online` 只说明密钥和开关已经加载，不代表服务商一定允许当前模型调用。

## 常见状态码

| 状态码 | 常见原因 | 处理方式 |
|---|---|---|
| `401` | API Key 无效或未加载 | 重新生成密钥，检查 `.env` 并重启 |
| `403` | 账号、模型或地区无权限 | 在服务商控制台确认模型权限 |
| `404` | Base URL 或模型名错误 | 核对兼容地址和模型 ID |
| `429` | 频率限制、并发限制或余额不足 | 降低请求频率，检查套餐和余额 |
| `500` | 本地处理或上游返回异常 | 查看运行终端最后几行日志 |
| `502/504` | 中转站上游异常或超时 | 稍后重试或更换稳定线路 |

## 密钥安全

- 不在聊天、截图、README、Issue 或代码中展示真实密钥。
- 不把 `.env` 上传 GitHub，公开仓库只保留 `.env.example` 占位符。
- 为不同项目创建不同密钥，并设置额度或消费告警。
- 密钥一旦公开，应立即在服务商控制台作废并重新生成。
- 中转站能够看到请求内容，不要上传真实企业机密、凭据或未脱敏日志。
