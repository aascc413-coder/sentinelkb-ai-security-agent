## 0. 范围决定

- **范围**：全闭环 P2–P5.1 —— 基础设施 → 三基线 → Proposed 方法 → 5 案例四方法对照（M8a 工程验收 + M8b 真实模型探索）。
- **位置**：仓库根目录新建独立包 `investigation/`（按 `phase-1-design.md` 3.3 节布局）。不改动 SentinelKB 产品代码，CI 新建独立 job。
- **排序原则**：先底层再高层、先父依赖再子依赖 —— 每一层只依赖已完成的下层，每层独立可测、独立可验收。
- **验收方式**：主实现自检 → 辅助 AI 独立技术复核 → 提交并推送 → 核对所测提交的必需 CI → 自动进入下一里程碑。技术检查或 CI 未过则修复复验。用户参与产品选择与保留事项审批，不作为每阶段工程通过的默认门槛（详见第 7 节）。

2026-10-04 并行补充：用户授权优先实施不受外部验收进度影响的独立任务。只依赖已验收 M1 的 M3 通用工具与 M4 预算组件可在独立分支提前开发、自检和复核；完整里程碑的父依赖、五案集成及验收标准保持有效。分支 CI 通过仅证明该分支的已交付内容，不将准备组件标成完整 M3 / M4。任务与验证记录见 [通用组件交付](acceptance/m3-foundations-acceptance.md)。

### M1 契约分区与公共动作 Schema（父：M0）[P2.1 + R3/R5]

- **契约按访问边界分三区存放**（不沿用 Phase 1 单文件全量移植）：
  - 运行时侧 `src/evidence_investigation/state/`：Alert、Evidence、EvidenceLink、Hypothesis、EvidenceState、ToolCall/ToolResult/ToolRecord/Coverage（运行时可见面）、Budget、Usage、FinalAssessment、TraceEvent、StopReason 等；
  - 工具环境侧 `tools/`（server 实现 Side）：EnvironmentFixture、FixtureRule、覆盖/错误语义的判定输入；跨边界类型在运行时契约中定义、环境侧引用，不重复定义；
  - oracle/评测侧 `evaluation/`（包外）：OracleCase、ActionExpectation、CaseScore、AggregateMetrics 等，位于 agent 不可导入目录。
- `errors.py` / `validation.py` / `codec.py` 同原计划：UTC 时区、start<end、发布时间≤as_of、概率∈[0,1]、成本非负、ID 唯一、引用存在、来源与调用一致、最终证据 ⊆ 已获事实；非法即抛 `ProtocolViolation`。
- **公共动作 Schema（R5）**：所有方法共用的动作联合类型 `ToolAction(tool, arguments) | FinishAction(FinalAssessment)`；假设提案、充分性解释等 Proposed 专用输出 Schema 独立存放，不进入公共接口。
- **验收（P2.1/R3）**：错误引用、错误时区、非法参数均被拒绝；守卫测试能发现从 agents/ 导入 evaluation 或环境侧契约的违规；契约与 Schema 为 V4-3 的原始模型输出留存与 usage 对账字段预留设计（M4 实施前确定字段与计量口径）。
- **辅助技术验收**：① 查看三区契约布局与目录树，确认 oracle 契约不在包内；② 独立运行校验演示命令，构造至少 2 个非法输入（如错误时区、悬空引用），确认被拒绝且原因易懂；③（可选深入核查）抽查公共动作 Schema 未夹带 Proposed 专有字段——该边界已由开发方自检与守卫测试覆盖，提验时附测试结果。

### M2 数据集层与充分性判定表（父：M1）[R3/R4]

- `datasets/public|environment|oracle/`：5 个 PublicCase、5 个环境映射（**4 份物理 EnvironmentFixture 文件，C4/C5 共用同一份**）、5 份 OracleCase（真值、observable/critical/distractor fact keys、替代充分组合 sufficient_sets、状态相关可接受动作 expected_actions）。加载时 opaque ID 重映射并过 Schema 校验；oracle 不进任何 agent 可导入模块。
- **充分性判定表（R4，最高优先）`rubrics/`**：PowerShell 告警族的 TP 门槛 G0–G4、FP 门槛 B1–B3，每条门槛按五列定义——

  | 项目 | 内容 |
  |---|---|
  | 所需观察 | 哪些事实或记录能够参与判定 |
  | 程序检查 | 来源、实体、时间、hash、参数、覆盖范围等可机械核查条件 |
  | 模型解释 | 证据与假设关系的解释及其适用范围 |
  | 冲突处理 | 证据相互矛盾时如何阻断确定结论 |
  | 无法验证 | 返回 unknown，不因结构正确就接受 met |

  例：B1"符合批准任务"至少核对实际执行与批准记录的 host、账号、时间、任务、hash、参数；仅存在维护窗口不通过此门槛。规则**按告警族**定义，禁止按 case ID 分支；dev 阶段冻结版本。该判定表同时供 M7 运行时检查与 M5 离线评分引用，双方版本一致。
- **C4/C5 输入边界验收（R3/V4-2，按依赖分阶段）**：M2 只做**静态**验收——告警内容、环境数据、公开字段与规范化规则（动态 ID 等按预先定义的规范化规则处理，规范化不得掩盖真实内容差异）；同一合法查询下的**实际工具响应**与差异报告验收归 M3 承接；捕获**实际模型请求**、检查告警/工具描述/返回内容进入模型后的边界归 M5 承接——不因前期静态检查通过而省略。
- **验收**：fixture 加载校验全过；C4/C5 **静态**模型可见输入等价（工具响应级与模型请求级等价分别在 M3/M5 承接验收，V4-2）；判定表冻结且运行时/评分两侧引用同版本。M2 可独立验收，不依赖尚未实现的 M3/M4 模块。
- **辅助技术验收**：① 对照 `minimal-cases.md` 逐案抽查 fixture（建议 C1、C3、C4/C5），核对记录与覆盖规则一致；② 独立打开 `datasets/public/` 与 `datasets/oracle/`，确认公开输入不含真值与 critical/distractor 标注；③ 审阅充分性判定表全文，重点核对 B1 示例的五列条件；④ 运行 fixture 摘要命令，核对案例数与各工具记录数。

### M3 工具服务层 `tools/`（父：M1+M2）[P2.2]

- `server.py`：MockToolServer 实现 `InvestigationTools` 协议——请求规范化签名 → 按 query_rules 过滤（host/user/窗口/limit，SIEM 窗≤24h、history≤30d、上限 50）→ 状态判定（ok/empty/partial/unavailable/timeout/error，覆盖由环境报告，模型不可修改）→ ToolRecord 附 content_sha256/independence_group/reliability → 模拟成本/延迟。
- `signatures.py`：查询规范化与缓存（完全重复查询命中缓存、不再后端执行、照常记账）。
- `diff_report.py`（A3）：C4/C5 规范化比对差异报告——按**预先冻结**的规范化规则处理允许变化的运行元数据（call_id、实际耗时等），报告列明被忽略/规范化的字段及原因；不能在看到差异后临时扩大忽略范围。
- **验收（P2.2，完成节点：实施前按 V4-1 明确测试范围）**：5 案例可回放；不同调用顺序、同查询同结果；镜像日志同事实共享 fact_key 不虚增独立性；**空结果（empty）与数据缺失（unavailable/partial）语义严格区分**；history 不可用（C3）返回明确不可重试状态。边界测试**不承诺穷举所有合法参数组合**（V4-1）：覆盖每种工具操作、过滤规则和错误状态；对时间边界、未知实体、结果截断等设计代表性测试；以参数化或性质测试检查 C4/C5 在相同查询下的响应等价性；提供可核对的覆盖表（工具操作、过滤条件、覆盖状态、错误状态）；测试范围和未覆盖项随报告列明，不将有限测试描述为覆盖所有可能输入（人工抽查仅为补充）。模型可见元数据不得编码案例真值；共享环境是结构保证，测试需检查查询实现是否破坏该保证。
- **辅助技术验收**：① 独立用工具演示命令对 C1 发起查询（process_tree → network_events → asset），核对返回与设计文档记录一致；② 重复同一查询，确认缓存命中且内容不变；③ 对 C3 查 history，确认返回明确不可重试的 unavailable；④ 对 C4/C5 执行同一组合法查询，按冻结规范化规则审阅差异报告：模型可见业务内容、覆盖状态和成本语义一致，被忽略/规范化的字段及原因已列明（A3）。

### M4 运行时层与公共 Evidence Registry（父：M1+M3）[P2.3 + R2]

- **公共 Evidence Registry（`runtime/registry.py`，四方法共用，R2）**：来源登记、确定性字段提取、ID 分配、fact_key 去重、原文引用（RawReference+hash）、call_id 关联。基线与 Proposed 获得等价的事实与引用能力，基线运行不依赖 `agents/`；注册器不访问 oracle；模型生成文本（摘要、风险分、自由"事实"）不得登记为事实。工具返回的 coverage/error 保存为原始响应 envelope，可引用"某数据源不可用"这一操作事实。
- `budget.py`：统一预算控制器——tool_attempts 计所有尝试（含错误/重试/缓存/非法请求），tokens 用"输入估算法+预留最大输出+终结评估预留"，monotonic deadline，step 计数；预算耗尽且无有效结论 → **确定性 Abstain**，禁止免费 LLM 补总结。调用前记录输入预估、输出额度与终结评估预留，调用后记录实际 usage 并与预估**对账**（V4-3B）：usage 缺失明确标记、不填零、不混作精确计量；发现超支即停止后续调用并记录偏差，不声称估算方式保证绝不超限；无法可靠计量的运行不参与严格的等 token 预算结论。
- `dispatcher.py`：校验 tool/参数类型匹配、注入 ToolContext（run_id/call_id/as_of/剩余超时）、强制"调用实体必须来自 alert 或 Registry 已获记录"（校验台账即公共 Registry）、瞬态错误重试一次（计费）、永久不可用不再查询、终止后迟到响应丢弃但费用照记、冗余签名台账。
- **M1 辅助复核承接（H1/H3）**：用完整 tool→参数类型映射表检查 Python ToolCall（含 Proposed 的 candidate.call），不依赖模型 JSON Schema 已验证这一假设；最终 evidence_id 列表的去重 / 重复拒绝另作公共检查，fact_key 去重不等于输出引用列表唯一。
- `trace.py`：每 run 写 `runs/<run_id>/manifest.json + events.jsonl + final.json`；事件含 sequence/UTC/elapsed/step/state_version 前后/usage 快照；覆盖设计稿 12 节全部事件类型。
- `model.py`：`ModelAdapter` 协议 + `OpenAICompatAdapter`（httpx，JSON 输出解析、非法输出最多修复一次且计费、usage 捕获含 reasoning）+ `FakeScriptedModel`（按阶段脚本化响应，供全部离线测试与 M8a）。每次模型调用同时保存**原始输出、校验错误、修复后输出与最终接受结果**（V4-3A）——四者属运行日志，不得登记为真实 Evidence。
- **验收（P2.3/R2）**：相同告警或工具响应经公共注册器得到等价事实与引用；所有调用计费可审计；超时/重复/迟到结果正确处理；trace 足以离线重放；初始证据已充分且其他预算允许时，不因 tool_calls=0 而禁止有依据的结论（含对应测试，A4）。注入一次虚假引用后，trace 能同时看到模型原始错误、拦截原因与最终接受结果，而非仅一个看似安全的最终 Abstain（V4-3A）；账本能区分预估 token、实测 usage 与未知值（V4-3B）。
- **辅助技术验收**：① 用假模型脚本跑一次完整 run，独立打开 `runs/<run_id>/` 三件套（manifest/events/final），核对事件顺序与 usage 累计；② 构造一次工具错误与重试，确认两次都计费；③ 对初始证据不足、必须查询工具才能判定的案例（如 C4）设 max_tool_calls=0，确认不执行工具，并在无已验证充分结论时输出确定性 Abstain、无额外免费模型总结（A4）；④ 对含镜像记录的查询确认 fact_key 去重；⑤ 观察虚假引用注入演示：同时看到模型原始错误、拦截原因与最终结果三段记录（V4-3A）。

### M5 评测核心 `investigation/evaluation/`（父：M1+M2+M4）[P2.4 + R3]

- `metrics.py`：实现设计稿 10.1–10.4 全部指标**定义**并保存计算所需原始数据；分母为 0 → NA 并展示分子/分母。小样本阶段报告只含**原始计数与逐案例结果**；bootstrap/零事件置信上界、Risk-Coverage 曲线、ECE 等校准展示延后到数据扩充后（指标定义与所需数据本轮固定下来）。
- `evaluator.py`：离线评分器——只读 OracleCase+Trace+FinalAssessment，独立于 agent（**不调用运行时自评**）；provenance 校验、语义 grounding、充分性按替代充分组合评分、动作按状态相关可接受集合评分。
- `replay.py`：从 events.jsonl 确定性重建最终状态，不调模型不调工具。
- **泄漏检查（R3）**：基于**隐藏字段、专用金丝雀标记、数据来源**做结构化检查（fixture 金丝雀字段、oracle-only 字段清单、case 语义 ID 反查、prompt 与工具响应逐条核对），**不以 malicious/benign 关键词匹配为主要手段**——这两个词合法出现在 TI verdict 与假设 kind 中，检查不得误报正常假设与 verdict。
- **实际模型请求边界检查（V4-2，承接 M2/M3）**：捕获实际发出的模型请求，检查告警、工具描述与工具返回内容进入模型后的边界——oracle 标注与隐藏字段不出现在任何实际请求中；静态与工具级检查通过不豁免本项。
- **错误与计量口径拆分（V4-3）**：分别统计**模型提案的证据错误**与**系统最终交付的证据错误**；False Close Rate 针对最终交付决策，被拦截的错误判断单列；成本报告区分预估 token、实测 usage 与未知（缺失不填零），无法可靠计量的运行不参与严格的等 token 预算结论。
- **验收（P2.4/R3）**：手算指标样例 = 报告结果；agent 执行路径无 oracle 读取；测试能发现故意混入提示的隐藏标记，且不对正常业务词误报；未获证据的引用被拒绝。端到端输入检查（实际模型请求级）在本里程碑完成（V4-2）；验证原始/最终错误分开统计与计量三态口径（预估/实测/未知，V4-3）。
- **辅助技术验收**：① 审阅指标定义文档（公式与分母约定），抽 2 个指标（建议 False Close Rate 与 Decision coverage）在手造小样本上自己计算，与 evaluator 输出比对；② 观察泄漏检查演示：故意注入金丝雀标记的用例被抓出，而含 malicious/benign 的正常假设与 verdict 不误报；③ 查阅开发方提供的评分独立性自检结果（代码检查与测试报告），源码走查作为可选深入核查（A2）。

### M6 基线层 `baselines/`（父：M1–M5）[P3.1+P3.2 + R5]

- 四方法（`direct` / `fixed` / `fixed_all` / `react`）全部基于 M1 **公共动作 Schema**（ToolAction|FinishAction）与 M4 **公共 Registry**：统一预算控制器、Dispatcher、Trace、输出 schema、重试规则；Fixed 冻结顺序 SIEM→TI→ATT&CK（fixed_all 含 5 工具，顺序冻结），步骤由 alert+确定性解析规则生成，查不到 indicator 记 stage_skipped；ReAct 逐轮自主决定工具或结束，**不被要求填写**假设关联、证据缺口、判别价值等 Proposed 专有字段。
- Proposed 的 InvestigationPlan 通过**适配层**转换为公共 ToolAction 下发，额外状态（假设、缺口、优先级分量）保留在其内部，不进入共享接口。
- 提示模板入 `prompts/` 并版本化，hash 入 manifest。
- **验收（P3.1/P3.2/R5）**：同一输出 schema 与预算口径；Fixed 顺序真实冻结可审计；ReAct 独立调用工具或结束；共享接口未隐式携带 Proposed 机制；四方法证据引用能力等价（同源重复不增加独立证据）。
- **辅助技术验收**：① 对 C1 分别运行四种方法，独立查看各自 trace：Direct 无工具调用、Fixed 顺序恒为 SIEM→TI→ATT&CK、ReAct 自主选择动作；② 比对四方法 final.json 字段结构一致；③ 查阅守卫测试结果（ReAct 模型消息不含 Proposed 专有字段的自动化断言），可选独立抽查（A2）。

### M7 Proposed 层 `agents/`（父：M1–M6）[P4.1–P4.3 + R4]

- `hypothesis.py`（P4.1）：竞争假设（≥1 恶意 + ≥1 良性，≤4 个具体假设，保留 other/unknown 通道）、expected/falsifying observations、EvidenceLink 支持/反驳分离、supersedes 修订、假设只能引用已存在 evidence_id。
- `sufficiency.py`（P4.2）：**消费 M2 判定表**——程序检查确定性执行（来源、实体、时间、hash、参数、覆盖范围逐项核查）；模型解释仅负责证据-假设关系并过 Schema 校验，**格式正确但引用不支持判断的 met 被拒绝**；缺失字段与覆盖不足 → unknown；冲突按判定表阻断确定结论；rubric 版本冻结。仅 PowerShell/白名单/unknown TI/ATT&CK 映射不得成立 TP/FP。
- `planner.py`+`investigator.py`（P4.3）：候选动作 ≤3（含各可能结果的支持/推翻预测）、冻结序数优先级公式 `3*discrimination+2*critical_gap+counterevidence+availability-cost-redundancy`、终止前"遗漏关键缺口"检查、主调查循环（context→hypothesis→Registry→sufficiency→planner→budget guard→dispatcher）、Suspicious/Abstain 分流规则与 stop_reason 分字段、硬预算耗尽必须 Abstain（保留 risk_flags）。
- **验收（P4.1–P4.3/R4）**：不同可见状态选不同工具；不支持的 met 被拒绝、覆盖不足得 unknown；C3 判 Suspicious 而非 FP；C4/C5 均 Abstain；反证、停止、拒判全程可追踪。
- **辅助技术验收**：① 对 C1/C2/C3/C4 各跑一次 Proposed（假模型与确定性逻辑验收口径，见 7.3），对照预期（TP/FP/Suspicious/Abstain）核对最终结论与所引用证据；② 独立演示一次充分性拒绝：构造结构正确但证据不支持的 met 输出，确认被拒；③ 审阅 planner 决策记录（选中与放弃的候选及理由）；④ 在 trace 中抽查假设只引用已存在的 evidence_id。

### M8a 工程验收报告（假模型）（父：M1–M7）[P5.1 部分 + R1/R6]

- FakeScriptedModel 全量运行 4 方法（+fixed_all）× 5 案例 × 3 重复：验证流程、预算、Trace 与计分实现的正确性；预算扫描 tool_budget=2/4/6/8 冒烟。
- **报告性质标注（R1）**：明确标注"假模型、工程验收"，验证的是流程与指标实现，**不得包含任何算法优越性或策略收益结论**。
- **报告-记录对应（R6）**：附运行配置、模型/数据/代码/工具/rubric 版本、逐案例结果、trace 文件清单与哈希；保存脱敏后的代表性成功与失败 trace 并注明完整归档位置；区分"重放已有记录重算指标"与"重新调用模型运行"（重跑分配新 run_id，不覆盖旧运行）。
- **验收**：能从报告定位对应 run 并用保存记录重算核心指标；全拒判、猜对无据、工具故障均不成为胜利指标，失败 run 单列；报告只含原始计数与逐案例结果，无统计推断。
- **辅助技术验收**：① 通读报告，确认标注"假模型、工程验收"且无任何策略优越性表述；② 从报告中任选一个 run，按 trace 清单找到对应目录，用重放命令重算一个核心指标，确认与报告一致；③ 确认失败 run 单列、原始计数无统计推断。

### M8b 真实模型探索报告（父：M8a + 本地 `.env` 可用）[R1/R6]

- 在相同模型条件下（同快照、同参数、同预算）真实运行 5 案例，观察实际行为与失败模式，**失败 trace 全部保留**。
- **结论边界（R1）**：探索性质；五个公开设计案例（含相关双胞胎 C4/C5）即使真模型运行也**不构成泛化能力或策略优越性证明**；报告标注模型模式与结论边界。
- **通过口径（A6）**：M8b 验收实验条件、执行正确性、记录完整性与结论诚实性，不要求真实模型达到预设效果；实验结论（支持/不支持/证据不足）与工程验收结论分开记录（见 7.3）。
- 未执行前，所有交付物将 M8b 标记为**未完成**；真模型走现有 `.env` 惯例（OPENAI_API_KEY/OPENAI_BASE_URL），费用用户自控。
- **验收**：报告可定位每个 run；结果不支持预期时保留失败 trace，不删困难样本、不改标签。
- **辅助技术验收**：① 用户批准付费资源及费用上限、提供必要凭据后，主实现执行真实模型运行并记录实际 usage / 费用，辅助 AI 独立核对执行条件和记录；② 辅助 AI 通读探索报告，确认标注模型模式与结论边界；③ **有**失败运行时至少抽查一个失败 Trace，**无**失败时记录失败数为零并抽查其他运行——失败记录保存机制由单独的故障注入测试验证，故障注入结果不混入真实实验统计（A5）。用户不承担例行执行或技术验收。

## 3. 关键技术决定

1. **隔离口径（R3）**：MVP 为**逻辑隔离**——三边界契约分区、包布局、导入守卫测试、数据不交叉引用、实际模型输入泄漏检查；明确其保证范围，不宣称进程/文件级隔离；子进程沙箱延后。
2. **模型双轨与结论边界（R1）**：CI/单测/M8a 用 FakeScriptedModel（仅工程验收，不出策略结论）；M8b 真实模型探索（OpenAICompatAdapter + `.env`），两者报告分开命名、分开验收。
3. **公共 Registry 与公共动作 Schema（R2/R5）**：证据加工与引用能力四方法等价；ReAct 不继承 Proposed 内部结构；Proposed 计划经适配转换为公共动作。
4. **C4/C5 不可区分性（R3/A3）**：共享同一 environment fixture + 逐字段核对实际模型可见输入 + **预先冻结**的规范化规则与差异报告（列明被忽略字段及原因），构造性消除泄漏面。
5. **依赖与 CI（R7）**：仅 jsonschema+httpx，依赖锁定；独立 CI job 干净环境安装测试，两套结果分开显示。
6. **统计边界**：小样本只报原始计数与逐案例结果；置信区间、Risk-Coverage 曲线、校准分析延后至数据扩充。
7. **里程碑提交与 CI 顺序（v6）**：本地主实现自检与辅助独立复核通过 → 提交并推送本项目开发变更 → 远端 CI 核对所测 commit 与冻结实现并通过 → 里程碑完成并自动推进；影响已验收行为的修复须由辅助 AI 复核受影响项。授权边界见第 7 节。

## 4. 明确不做（本轮）

- P5.2（30–100 案例扩充、消融）、P6（SentinelKB 检索接入为工具、真实 SIEM、其他告警族）、Web UI、API 集成、MCP。
- bootstrap 置信区间、零事件上界、Risk-Coverage 曲线与 ECE 展示（先固定指标定义、保存所需数据）。
- 子进程级隔离加固（逻辑隔离已声明的保证范围之外）。
- 文件数/测试数等数量承诺（改用风险验收清单）。

## 7. 技术验收与自动推进（v6）

### 7.1 每里程碑流程

1. **主实现自检**：实现范围内工作，运行必要自动测试和演示，检查具体剩余风险；保留报告与失败证据。
2. **冻结提验版本**：保存源码 / 数据 / 判定表的文件清单与完整哈希、命令、环境、测试结果和已知限制。提交字节使用 Git blob 哈希；工作区字节与提交字节的换行差异另列，不能用规范化掩盖业务差异。
3. **辅助 AI 独立复核**：在独立 worktree 或副本中核对版本，复现必要验证、检查边界与缺口，提交通过 / 不通过结论。辅助可由独立会话或独立子代理承担；职责是复核，不代写主实现的自检结论。
4. **修复与提交**：技术检查均通过后，主实现按已获授权提交并推送本项目开发变更。修复保留问题历史；修改影响已验收行为时，复核受影响项。
5. **远端 CI 验证**：核对 `test` 与 `investigation-tests` 都成功，核对实际 head SHA 包含被冻结的实现。CI 未完成 / 失败时标记待远端验证 / 待复验，不能写成完成。
6. **自动推进**：前三项技术门槛（自检、独立复核、同一提交 CI）齐备后，标记阶段完成并开始依赖它的下一阶段。状态记录的后续文档提交保留实际所测 SHA，不能把未测试的新代码冒充已验证版本。
7. **用户知会与例外**：给出一分钟内可读的完成能力、验证证据、限制和下一步摘要，不等待例行回复。发布、付费资源、真实安全处置仍需单独同意；业务范围改变、实验需要新费用上限、无法自行解决的产品选择再交用户判断。

一次授权覆盖本项目范围内的开发提交与推送。不得将 AI 技术复核记录伪写成用户执行过的人工验收，也不得把工程通过当作研究假设已成立。

### 7.3 工程验收与实验结论分开判断

| 情况 | 处理方式 |
|---|---|
| 漏记调用、预算失效、标签泄漏、评分错误 | 技术验收不通过，修复后由辅助复核受影响项 |
| 假模型流程不符合预设行为 | 检查实现或脚本，修复并保留问题记录 |
| 真实 Proposed 更贵、拒判更多或没有减少错误关闭 | 如实验执行正确，工程可以通过；如实记录研究假设未获支持或证据不足 |
| 真实输出偏离预期 | 区分实现缺陷与策略表现，再决定修复或作为实验发现保留 |

M7 固定预期用于假模型和确定性逻辑；M8b 验证实验执行与结论诚实性。不得为了通过验收删困难样本、改真实标签或只留有利运行。策略调整创建新版本、新运行，保留旧结果。M8b 如涉及收费模型调用，需先获得明确费用上限；没有授权时保留未完成，不用假模型替代真实实验结论。
