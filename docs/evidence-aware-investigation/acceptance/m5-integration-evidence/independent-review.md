# M5 集成组件独立审查

审查时间：2026-10-22。审查者：辅助代理 `m5_replay_review`；修复与最终复验：主代理。

## 审查范围

- `evaluation/evaluator.py`：事实映射、来源真实性、结构化 grounding、充分集合、原始提案与最终交付分离。
- `evaluation/behavior.py`：动作前状态、动作标注覆盖、重试、重复查询和效率原始计数。
- `evaluation/leakage.py`、`evaluation/report.py`：实际请求捕获、策略检查、失败运行保留。
- 五案工程集成和 evaluator/import 守卫。审查时针对范围内 32 项测试通过，并另写独立探针。

## 独立发现与处置

1. **瞬态失败后再次查询被错算冗余。** 根因是首次请求发出后立即登记 `seen`，没有等待稳定结果。修复为只有完整、未截断、无缺源的 `ok/empty` 结果或永久不可用结果才建立已知重复依据；迟到和协议错误不登记。回归测试证明三次人工同查询在“瞬态失败 → 成功 → 重复”时只把第三次计为冗余。
2. **最终 token 汇总可篡改为零。** 新增离线 model reservation/output/reconciliation 生命周期核对，校验调用数、实测输入输出 token、完整性和货币费用。覆盖格式修复的两次尝试、未知/部分 usage、工具未知 usage、缺失/重复 reserve 或 settlement、事件 snapshot 与最终 usage 篡改。
3. **未转交 adapter 的捕获仍可通过。** 报告现在拒绝 `forwarded=false` 的捕获，避免把拦截请求当作已执行模型调用的输入证据。
4. **捕获与报告使用不同策略时发现可能丢失。** 报告合并捕获时已记录 finding 与报告阶段复检 finding，较宽松的后续策略不能抹除边界发现。

## 最终结论

上述问题均已有自动回归。随后对冻结标注与持久化层复核，又发现并修复四项问题：合法公共 `rationale` 误报；缺失 capture 未转失败；空风险 Suspicious 被排除分母；结构不完整 capture 可通过。辅助代理用原探针复验，相关五组 65 项通过，本范围无剩余阻塞。最终完整调查包测试 637 项通过。

审查确认 M5 工程契约、冻结五案标注和失败检测；不确认 Agent 优于基线，也不构成真实模型实验结论。
